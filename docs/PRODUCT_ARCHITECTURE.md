# LaLea 產品與系統架構草案

> 狀態：需求探索中，暫緩正式開發  
> 最後更新：2026-08-21

## 1. 文件目的

本文件用來記錄 LaLea 目前已確認的產品方向、初步系統架構與尚待討論的決策。在產品方向定型以前，不將現有概念稿視為正式規格，也不擴大功能開發。

## 2. 產品定位

LaLea 取自 **Language Learning**，是一個以實際情境與可持續複習為核心的多語言學習平台。第一個內容產品專注於職場英文，但平台架構不將英文、中文或單一學習方向寫死。

目前的核心定位：

- 優先幫助使用者累積單字與片語。
- 把詞彙放入真實職場情境，而非只做單字卡記憶。
- 同時培養閱讀、聽力、口說與表達能力。
- 以每日短時間、可持續的學習為主要使用模式。
- 支援手機網頁與不需持續注視螢幕的音訊學習。
- 以「學習路徑」組織一種源語言到一種目標語言的課程、詞彙、複習與能力進度。
- 未來可在不重建核心架構的前提下，加入日文、韓文、西班牙文或其他語言學習路徑。

## 3. 目標使用者

### 第一階段

- 主要供專案擁有者個人使用。
- 功能與課程可依個人需求快速調整。

### 架構原則

- 即使第一階段只有一位使用者，資料模型仍以多使用者為前提。
- 學習進度、詞彙狀態、收藏、複習排程與個人偏好皆必須歸屬於明確的 `user_id`。
- 課程、共用詞彙與情境素材與使用者資料分離。
- 每位使用者可同時擁有多條學習路徑，各路徑的程度、進度、複習排程與偏好彼此獨立。

## 3.1 多語言學習路徑

一條學習路徑（learning path）至少由以下資訊定義：

- **目標語言**（target language）：使用者正在學習的語言，例如英文。
- **輔助語言**（support language）：用於解釋、翻譯與介面提示的語言，例如繁體中文。
- **主題或領域**：例如職場、旅遊或日常生活。
- **程度與能力框架**：例如 CEFR，但不假設所有語言都只使用同一套等級。
- **學習目標**：例如詞彙、口說、聽力或綜合能力。

第一條學習路徑預設為：

> 繁體中文輔助 → 職場英文，以單字與片語為重點的綜合能力學習。

輔助語言不等於網站介面語言。使用者可能使用繁體中文介面，但選擇英文或其他語言作為輔助語言。兩者必須分開記錄。

## 3.2 第一位目標使用者的學習輪廓

### 目前能力

- 英文 Email、文章或技術文件約可理解 80%，但仍會使用翻譯工具協助確認。
- 初步估計不屬於英文初學者；實際 CEFR 等級尚未經分級評量，不先固定為特定級別。

### 主要摩擦點

- 聽力高度依賴注意力與字幕；環境稍微吵雜或分心時，對連音、弱讀與完整句意的辨識容易中斷。
- 英文寫作時不確定文法是否正確。
- 即使文法正確，仍不確定用語是否自然、夠口語化，或適合客戶與面試情境。

### 專業背景與目標

- 領域：半導體與 PCB。
- 主要目標：強化未來英文面試與求職能力。
- 主要目標：提升與客戶溝通、澄清問題、解釋技術狀況與回報進度的能力。
- 第一階段內容範圍：先以通用商務英語建立共通能力，不要求使用者現在就定義具體半導體或 PCB 案例。
- 後續內容擴展：再將半導體、PCB 客戶溝通與技術面試作為專業主題模組。

### 課程設計含意

- 少花時間在過於基礎的文法解說，改以「輸出後即時診斷」補強真正的錯誤。
- 並列正確但不自然、自然口語、對客戶的專業說法與面試說法。
- 聽力練習應提供字幕逐步減量，而不是從一開始強制關閉字幕。
- 音訊練習應包含正常語速、連音與輕度干擾條件，同時保留降速、重播與逐句對照。
- 詞彙應同時包含通用職場片語與半導體、PCB 領域詞彙，並優先練習能完成溝通任務的搭配詞與完整句型。
- 第一階段先建立通用商務詞彙與溝通任務，包括自我介紹、會議、進度回報、問題澄清、Email、客戶回覆與面試；專業領域詞彙稍後加入。
- AI 回饋應拆分「文法正確性」、「自然度」、「正式程度」與「任務是否完成」，不只給一個總分。

## 4. 核心學習體驗

### 4.1 每日短課與微型學習單元

使用者希望盡可能利用零散時間學習。因此，LaLea 不將「一堂課」定義為必須一次連續完成的十多分鐘內容，而是由多個可獨立完成、可中斷與可續接的微型學習單元組成。

初步時間層級：

- **單一微型單元**：約 1–3 分鐘，完成後立即產生可保留的學習進度。
- **一堂主題課**：約由 4–6 個微型單元組成，可跨多次使用完成。
- **每日目標**：以累計學習量或完成單元數表示，預設可約為 10–15 分鐘，但不要求連續完成。
- **音訊模式**：可使用較長的播放清單，並在非視覺操作情境中累積聽力學習時間。

一堂商務英語主題課可由以下微型單元組成：

1. 今日單字與片語，預計 5–8 個。
2. 詞性、中文解釋、發音、例句與常見搭配。
3. 實際職場情境對話。
4. 理解題、填空、聽力或句子組合練習。
5. 固定答案或有限分支的情境應用。
6. 課後將不熟悉的內容加入複習排程。

上述步驟不要求在同一次 session 中完成。第一版不包含開放式問答或自由對練。

### 4.1.1 零散時間設計原則

- 開啟網站後，應能在極少操作內開始下一個合適的學習單元。
- 每個單元開始前顯示預計需要的時間與互動類型，例如「1 分鐘／可靜音」或「3 分鐘／需聽音」。
- 單元完成後立即儲存結果，不以完成整堂課為儲存條件。
- 離開頁面、應用程式進入後台或網路中斷時，應保留可安全續接的檢查點。
- 系統應能依當前可用時間、是否能播放聲音、是否能說話與當日目標，建議合適的單元。
- 不因使用者只完成一個微型單元而顯示失敗或中斷感；每次有效練習都應有明確的完成回饋。
- 重複性很高、未產生有效互動的快速點擊不應被計入學習時間或熟悉度。

### 4.1.2 第一版預設學習體驗

以下細節採用已知有效的學習方法作為第一版預設，不需要使用者逐項決定：

#### 開始學習

- 首頁主要操作為「繼續學習」，系統自動安排下一個合適單元。
- 使用者可快速告訴系統自己約有 1、3 或 5 分鐘。
- 互動環境預設為「靜音」、「可聽」、「可說」與「純聽」，系統記住最後使用狀態，但允許當次快速改變。
- 排程優先完成已到期的複習，再加入少量新內容。

#### 第一版微型單元

1. **情境導入**：以一個實際商務句子介紹單字或片語，不只展示孤立翻譯。
2. **閱讀辨識**：從英文判斷詞義、使用情境或自然度。
3. **聽力辨識**：聽句子後選擇意思或關鍵詞。
4. **主動提取**：以選擇、排序、填空或固定句塊組合回想英文片語，作答後立即顯示回饋。
5. **自然度與改寫**：比較「文法正確」與「實際商務情境更自然」的說法。
6. **短對話應用**：在一到三輪對話中使用目標詞彙完成溝通任務。

第一版優先實作上述單元。複雜發音評分、長篇自由對話、遊戲化與大量題型先不列入最小原型。

### 4.2 情境對話

可能的職場情境包含：

- 日常同事交流
- 會議發言與回應
- Email 與即時訊息
- 簡報與提案
- 專案進度回報
- 與主管、同事、客戶或跨部門對象溝通
- 面試與職涯發展

對話內容應標記對象、正式程度、情境與難度，避免將所有英文統一改寫成過度正式的語氣。

### 4.3 情境對練與未來 AI 對練

MVP 只提供可預先定義與可靠判定的情境練習：

- 選擇合適回應。
- 排序句子或組合固定句塊。
- 從有限選項完成一至三輪分支對話。
- 以預先編寫的回饋說明語氣、文法與使用情境。

暫不納入文字或語音的開放式回答、自由改寫及即時生成後續對話。這些能力保留為後續階段，等內容品質、評分可靠度、服務成本與隱私邊界完成驗證後再評估。

固定練習的回饋可包含：

- 表達是否自然
- 文法與用字問題
- 語氣是否適合溝通對象
- 更常見或更符合職場情境的說法
- 是否正確使用本課目標詞彙

AI 在 MVP 中只協助操作者離線產生與審核教材，不直接評分學習者的開放式回答。

### 4.4 單字與片語複習

每個詞彙對每位使用者應有獨立學習狀態：

- 新內容
- 正在學習
- 容易忘記
- 已熟悉
- 暫時忽略

資料模型應保留以下資訊，以支援後續導入間隔重複演算法：

- 上次複習時間
- 下次複習時間
- 答題或自我評估結果
- 累計練習次數
- 答對、答錯與連續答對次數
- 熟悉度或記憶強度

#### 第一版掌握度模型

同一詞彙至少分開記錄：

- **閱讀辨識**：看到後能否理解。
- **聽力辨識**：聽到後能否辨識與理解。
- **主動表達**：在沒看到答案時能否回想，並在情境中正確使用。

「口語發音品質」先保留獨立擴充位置，不在第一版假設系統能精準評分。使用者手動回饋預設為四級：「忘記」、「困難」、「掌握」、「太容易」。

#### 第一版複習策略

- 採用間隔練習與主動提取，作答後提供立即回饋。
- 每個掌握度面向有獨立的複習狀態，例如「看得懂但聽不懂」不會被誤判為全面掌握。
- 到期複習優先於新內容；當次時間極短時，優先安排一到數個到期項目。
- 第一階段預設每日新增 3–5 個核心單字或片語，並可依累積複習量自動降低。
- 實作時採用可替換的排程器介面，保留完整作答事件，以便後續調整或導入 FSRS 類型的自適應演算法，而不遗失歷史資料。
- 使用者可將明顯過於簡單的詞彙標記為「暫時忽略」，並可隨時恢復。

### 4.5 字幕與聽力支架

字幕不視為需要立即移除的依賴，而是可逐步減少的學習支架。第一版預設階段：

1. 先聽一次，允許使用者直接開啟完整目標語言字幕。
2. 第二次優先顯示關鍵詞，而不是完整句子。
3. 作答後顯示完整文稿、連音或弱讀提示與中文說明。
4. 同類內容表現穩定後，系統建議延後顯示字幕，但不禁止使用者手動打開。
5. 輕度背景干擾只在無干擾條件下已有穩定表現後才加入，且可關閉。

預設使用目標語言字幕進行聽音與文字對齊；中文用於作答後的理解輔助，不在所有聽力播放中預設常駐。

## 5. 音訊與循環播放

音訊學習是核心功能，不只是單句發音按鈕。

### 預計播放內容

- 英文單字或片語
- 英文後接中文意思
- 英文、中文意思與英文例句
- 單句循環
- 完整情境對話
- 今日課程播放清單
- 待複習詞彙播放清單

### 預計播放設定

- 語速
- 句子間隔
- 重複次數
- 單曲或整份清單循環
- 中英文播放順序
- 是否播放例句

### 通勤模式

介面優先提供播放、暫停、上一句、下一句與標記不熟等低視覺依賴操作。

> 注意：「手機瀏覽器鎖定螢幕後繼續播放」需先驗證 iOS、Android 與主要瀏覽器的實際限制，目前不視為已保證的功能。

## 6. 額外詞彙注入

使用者應可將課程外的單字與片語加入個人詞彙庫。

### 可能的輸入方式

- 手動輸入單字或片語
- 批次貼上詞彙清單
- 貼上一段英文，再擷取其中的重要詞彙
- 從課程或情境對話一鍵加入
- 未來可考慮 CSV、文件或網頁匯入

### 詞彙資料

- 原文
- 種類：單字或片語
- 詞性
- 中文解釋
- 發音或音標
- 英文例句與中文翻譯
- 常見搭配
- 職場使用情境
- 難度
- 來源
- 自訂標籤與備註

AI 可協助補齊詞彙資料，但使用者應可在儲存前確認或修改，避免錯誤內容進入複習庫。

### 6.1 核心詞彙的資料來源

目前概念稿中的句型為介面展示用內容，不來自正式字典、教材、公開資料集或資料庫，不視為已審核教材。

正式版本預計採用混合來源：

- **可追溯的語言資料**：由授權明確的開放詞典、資料集或商業字典 API 提供基礎詞義、詞性與發音資料。
- **人工編寫與審核**：用來建立核心職場詞彙、語氣說明與重要使用情境。
- **AI 輔助內容**：產生或改寫職場例句、情境對話、搭配詞與練習題，但必須標記來源與審核狀態。
- **使用者注入**：由使用者手動輸入、貼上文本，或從課程與 AI 對話收藏。
- **YouTube 學習片段**：從使用者提供的 YouTube 影片連結建立帶時間碼的學習片段、詞彙與練習。

每筆詞彙應保留來源類型、來源識別碼、授權或使用條件、產生方式、審核狀態與最後更新時間。

### 6.2 YouTube 片段輸入

此功能的目標是將真實英文影片轉換為可複習的學習素材，而非建立 YouTube 影片的副本。

#### 建議使用流程

1. 使用者貼上 YouTube 影片連結。
2. 系統讀取允許取得的影片 metadata，並記錄 `video_id`。
3. 使用者選擇或輸入起訖時間碼。
4. 使用 YouTube 官方嵌入式播放器播放該時間區段，不自行下載與儲存影音副本。
5. 若有符合權限與授權的字幕或使用者自行提供的文稿，系統可從中擷取候選單字、片語與完整句子。
6. AI 補充詞義、職場用法、練習題與中文說明。
7. 使用者確認後，再將詞彙與片段加入個人學習庫。

#### 片段資料邊界

預計儲存：

- YouTube `video_id`
- 影片標題、頻道與原始連結等必要 metadata
- 起始與結束時間
- 使用者筆記與標籤
- 經過確認的詞彙、短句與學習解釋
- 字幕或文稿的來源、授權與取得方式

原則上不儲存：

- YouTube 影片或音訊檔副本
- 未經允許下載的完整字幕
- 無法追溯來源或授權的影片內容

#### 權限與平台限制

- YouTube 官方 `captions.download` API 需要 OAuth 2.0，且請求者必須有編輯該影片的權限；不能將「公開可看」直接視為「可透過 API 下載字幕」。
- 片段播放應優先使用 YouTube IFrame Player API 的起訖時間與播放控制。
- 嵌入播放需遵守 YouTube API 條款、開發者政策、影片嵌入限制與當地著作權規則。
- 教學用途並不自動等於合法的合理使用；對外提供服務前需再進行授權與法務評估。
- 影片被刪除、禁止嵌入或字幕不再可用時，系統應保留學習紀錄，但不應嘗試繞過限制恢復影音。

#### 第一版的建議範圍

- 由使用者貼上單支影片連結。
- 由使用者手動選擇時間區段。
- 使用 YouTube 官方播放器重複播放該區段。
- 字幕優先由使用者貼上或由影片擁有者授權取得。
- 從文稿擷取候選詞彙，經使用者確認後加入複習。
- 第一版不開發任意 YouTube 影片或音訊下載功能。

## 7. 資料與系統架構

### 7.1 目前實作狀態

- 現有網站是可拋棄的概念稿。
- Cloudflare D1 尚未啟用。
- Drizzle 資料層只有空白骨架，尚無資料表。
- 目前所有課程、句型與進度均為前端展示資料。
- 收藏狀態只存在當前頁面記憶體，重新整理即消失。
- 尚無真實的學習進度、詞彙注入、複習排程或 AI 對話儲存。

### 7.2 預計技術方向

- **主要程式語言**：TypeScript。
- **全端網頁框架**：Next.js。
- **介面層**：React，支援桌面與行動版瀏覽器。
- **樣式**：Tailwind CSS 與專案 CSS，實際使用邊界尚待確認。
- **預定正式環境**：使用者自有 Linux 主機。主機發行版、網路環境、容器策略與維運方式尚待確認。
- **過渡或預覽環境**：目前 Cloudflare Sites 只用於早期概念稿，不是正式架構前提。
- **主要資料庫**：PostgreSQL。
- **資料存取層**：Drizzle ORM。
- **彈性資料**：核心資料使用正規化關聯資料表；AI 回饋、題型設定與可變 metadata 可依需求使用 PostgreSQL `jsonb`。
- **PostgreSQL 部署**：目標 Linux 主機已安裝 PostgreSQL，第一版預設使用該主機上的既有服務；應建立 LaLea 專用資料庫與最小權限角色，同時保留未來改用獨立或託管 PostgreSQL 的標準連線介面。
- **檔案與預生成音訊**：若後續需要，可使用 Cloudflare R2；目前尚未啟用。
- **AI 與語音服務**：尚待評估。

Next.js、TypeScript、PostgreSQL 與 Linux 自架可攜性為目前已確認的技術基線。其他技術元件仍可在原型開發前調整。現有 vinext 與 Cloudflare D1 骨架都屬於早期概念稿，不代表正式專案架構。待開發階段開始時，應先確認 Next.js 版本、路由模式、PostgreSQL 部署方式與 Linux 主機相容性。

### 7.3 架構原則

- 使用者資料與共用教材分離。
- 課程內容與複習演算法分離。
- AI 產生內容不直接覆寫經過確認的教材。
- 原始學習紀錄與彙總結果分離，便於後續調整演算方式。
- 音訊播放清單由學習內容產生，不將其寫死在介面中。
- 所有使用者資料查詢都必須以已驗證的使用者身分隔離。
- 語言以 BCP 47 語言標籤或可對應的標準化識別碼儲存，例如 `en`、`zh-Hant`、`ja`。
- 不將 `english_text`、`chinese_translation` 這類特定語言寫入核心 schema；改以 `language_id`、`target_language_id` 與 `support_language_id` 表達。
- 介面本地化、教材語言、輔助語言與語音音色是四個不同概念，應分開建模。
- 詞彙不只是一個字串；應區分語言、寫法、詞義、翻譯、讀音與使用情境。
- 習得狀態歸屬於「使用者的某條學習路徑」，不只歸屬於使用者，避免多語言進度互相覆蓋。
- 排序、斷詞、文字方向、大小寫、變格、空格與發音規則不預設都與英文相同。
- 應用程式通過環境變數與標準介面連接資料庫、檔案儲存、AI 與語音服務，不將 Cloudflare 特定綁定寫入核心商業邏輯。
- 部署應可重複建立，包含明確的執行環境版本、資料庫 migration、設定模板、健康檢查、備份與還原流程。
- 開發工具、AI CLI 與正式網站執行環境應彼此隔離，避免網站請求直接取得主機上的終端、專案檔案或過度權限。

### 7.4 Linux 自架與 AI 工具

使用者的 Linux 主機已安裝 Codex 與 Claude。目前將兩者定位為：

- 輔助程式開發、設計、維護與故障排查。
- 半自動產生課程草稿、詞彙補充與內容審核建議。
- 在有明確人工確認與權限邊界下執行後台內容工作。

安裝 CLI 不等於 LaLea 正式應用程式可安全、穩定或合法地將它們當作 API。正式 AI 對練、自動詞彙處理與語音功能尚需另行確認：

- 可程式化的官方 API 或受支援服務
- 身分驗證與金鑰管理
- 使用量、費用、超時與重試控制
- 輸入與輸出的資料保留政策
- 失敗時的降級行為與人工審核流程

部署形態可在開發前比較：

- 容器化部署，例如 Docker Compose
- 主機原生服務，例如 Node.js 行程搭配 systemd
- PostgreSQL 與應用程式同機或獨立託管

在取得主機規格與維運需求前，不預先鎖定上述方案。

### 7.5 無 API key 的訂閱制 AI 與語音方案

目標是不使用按量計費的第三方 AI API key，優先使用現有 Codex 與 Claude 訂閱、瀏覽器能力與 Linux 本地服務。

#### 核心限制

- ChatGPT / Codex 與 Claude 的個人訂閱不視為通用的應用程式 API 授權。
- LaLea 網站不直接讀取、複製或代理 Codex / Claude CLI 的登入憑證。
- LaLea 網站不由網頁請求直接啟動具有主機檔案與終端權限的 AI CLI。
- 訂閱限額、交互式登入、工具版本與服務條款都可能改變，因此不將 CLI 行為當作正式網站的可用性承諾。

#### 系統邊界

```text
LaLea 網站
├─ 正常學習、複習排程與非 AI 題型
├─ 瀏覽器或 Linux 本地語音服務
├─ 建立「待處理 AI 任務」
└─ 匯入已審核的 AI 結果

操作者工作台
├─ 操作者主動使用已登入的 Codex 或 Claude
├─ 讀取待處理任務包
├─ 產生教材、詞彙補充或審核建議
└─ 將結果放入待確認區
```

操作者工作台與公開網站必須使用不同的系統帳號、檔案權限與執行邊界。

#### 訂閱 AI 負責的任務

- 批次產生每日課程草稿。
- 補充詞義、例句、商務情境與自然說法。
- 從使用者文本或授權字幕中擷取候選詞彙。
- 將課程草稿轉換成固定 JSON schema，供 LaLea 驗證與匯入。
- 檢查重複詞彙、翻譯異常、不自然句子與程度不一致。
- 針對使用者累積的錯誤紀錄，產生下一批課程建議。

所有結果預設先進入待確認狀態，不直接覆寫已發布教材。

#### LaLea 即時負責的功能

不需要第三方 AI API：

- 根據已建立教材出題、判分與顯示回饋。
- 間隔複習排程。
- 閱讀、聽力、填空、排序、選擇與固定短對話。
- 以預先生成的可接受答案、關鍵片語與規則評估短文字回應。
- 建立 AI 求助任務，稍後由操作者處理。

第一版不承諾以訂閱 CLI 提供即時 AI 自由對練。如使用者需要即時求助，系統可產生可複製的提問包，由使用者主動在 ChatGPT 或 Claude 中送出，再將結果匯回。

#### 無 API key 語音方案

| 功能 | 第一版方案 | 降級方案 |
| --- | --- | --- |
| TTS 發音 | 瀏覽器 Web Speech `speechSynthesis` | Linux 本地 TTS 預生成音檔 |
| 課程音訊 | Linux 本地 TTS 預先產生並快取 | 瀏覽器 TTS |
| STT 輸入 | Linux 本地語音辨識模型 | 使用者改用文字輸入 |
| 發音評分 | 第一版不自動評分 | 跟讀錄音與自我檢查 |
| 即時語音 AI | 第一版不提供 | 固定分支對話與本地 STT |

本地語音模型與音色需等取得 Linux 主機的 CPU、GPU、RAM 與磁碟規格後再選擇。

#### 任務狀態與審核

「待處理 AI 任務」至少包含：

- 任務類型與固定 schema 版本
- 輸入內容與來源
- 使用的操作者工具
- 狀態：待處理、處理中、待確認、已接受、已拒絕或失敗
- 輸出驗證結果與人工修改紀錄
- 創建、處理與審核時間

如未來開放多使用者且需要即時 AI 對練，就必須重新評估正式 API、本地模型服務或受支援的企業整合；不應透過個人訂閱 CLI 擴充成網站後端。

## 9. 非功能性需求

- **行動優先**：主要學習流程必須能在手機上單手操作。
- **無障礙**：支援鍵盤、輔助技術標籤與降低動畫設定。
- **可攜式內容**：課程與詞彙不與特定頁面結構綁定。
- **資料隱私**：AI 對話、錄音與學習紀錄需有明確保留與刪除規則。
- **成本可控**：AI 與語音服務應能記錄用量，並限制意外重複呼叫。
- **可測試性**：複習排程、進度計算與權限隔離應可獨立測試。

## 10. 待討論與未決定事項

### 學習內容

- 使用者目前的英文程度與目標程度
- 優先職場情境與工作領域
- 中文解釋的比例，以及是否隨程度逐步降低
- 每日課程的時間、詞彙數量與練習量
- 課程內容是人工編寫、AI 輔助或混合製作

### 複習系統

- 熟悉度的操作方式與評分尺度
- 第一版是否導入完整間隔重複演算法
- 單字、片語與完整句子是否使用同一套複習單位

### AI 與語音

- AI 模型與服務供應者
- 文字、語音輸入與即時對話的優先順序
- TTS 是即時生成、預先建立音檔，或使用混合方式
- 發音、口音、語速與中文語音需求
- AI 對話與使用者錄音的保留期間

### 帳號與存取

- 第一階段的登入方式
- 是否需要離線學習與後續同步
- 匯出、備份與刪除個人學習資料的需求

### 介面與產品形態

- 整體品牌、語氣與視覺方向
- 首頁應優先展示今日任務、待複習內容或學習成果
- 通勤模式是網站內的獨立頁面，還是類似播放器的全局模式

## 11. 階段規劃草案

### Phase 0：需求定義（目前階段）

- 確認目標使用者、英文程度與職場情境。
- 定義每日學習流程。
- 定義詞彙注入與複習流程。
- 驗證音訊循環與手機背景播放限制。
- 整理第一版的功能邊界。

### Phase 1：產品原型

- 只驗證核心學習流程與行動版操作。
- 使用少量代表性課程與詞彙。
- 不在此階段過早擴充內容量。

### Phase 2：可用的個人版本

- 啟用帳號、資料庫與學習資料持久化。
- 完成詞彙庫、複習排程、每日短課與音訊播放。
- 依驗證結果擴充固定分支情境練習；開放式 AI 對練另列為未來能力。

### Phase 3：多使用者擴展

- 驗證帳號隔離、同步、權限與資料保留規則。
- 加入不同程度、領域與個人化學習路徑。
- 依實際需求評估管理後台與內容編輯工具。
