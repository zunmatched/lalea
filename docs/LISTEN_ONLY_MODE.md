# LaLea 純聽／通勤模式規格草案

> 狀態：待使用者審查與裝置實測  
> 最後更新：2026-08-21  
> 範圍：MVP 手機網頁、低視覺依賴音訊學習

## 1. 目的

純聽模式讓使用者在走路、通勤、整理環境或不方便持續看螢幕時，仍能接觸與複習詞彙、片語和短對話。

這個模式主要增加聽力曝露、辨識與記憶提取機會，不把背景播放時間直接等同於學習成效。

## 2. 使用情境與安全

- 適合搭乘大眾運輸、步行、做簡單家務或休息時使用。
- 駕駛、騎車、操作機具或需要高度注意力時，只允許無需觸控的被動播放。
- 介面不鼓勵使用者在移動中閱讀字幕或進行複雜操作。
- 首次使用簡短提醒：請依環境安全決定是否操作裝置。

## 3. 進入方式

首頁將環境切換為「純聽」後，主要操作改為「開始播放」。使用者也能從下列位置進入：

- 今日學習首頁。
- 詞彙庫的選定清單。
- 特定主題課。
- 到期複習清單。

最短開始流程不要求先設定播放細節；系統沿用上一次偏好。

## 4. 播放清單來源

預設「今日純聽」依以下順序組成：

1. 已到期且需要聽力複習的內容。
2. 最近學過、聽力掌握較弱的內容。
3. 今日課程的核心片語。
4. 少量尚未熟悉的新內容；預設不超過清單的 20%。

使用者也可選擇：

- 只播到期複習。
- 只播某堂課或主題。
- 只播標記為困難或不熟的項目。
- 播放自選詞彙清單。

已暫時忽略、缺少可用音訊或內容未通過審核的項目不進入正式播放清單。

## 5. 播放單位

一個播放單位可以是：

- 單字或片語。
- 詞彙加中文核心意思。
- 詞彙加英文例句。
- 詞彙、中文意思與英文例句的組合。
- 一段短情境對話。
- 聽後停頓、讓使用者在心中或口頭回想的提示。

每個單位需要穩定識別碼與內容版本，才能正確記錄播放事件並在教材更新後追溯。

## 6. 預設播放腳本

### 新內容或較不熟內容

```text
英文片語
→ 短停頓
→ 繁體中文核心意思
→ 英文例句
→ 2–3 秒回想或跟讀空間
→ 英文例句再播放一次
```

### 已學過的聽力複習

```text
中文情境或溝通意圖
→ 3 秒回想空間
→ 英文片語
→ 英文例句
→ 簡短確認提示
```

### 短對話

```text
情境提示
→ 完整對話
→ 關鍵片語
→ 完整對話再播放一次
```

預設避免在每個片段之間加入冗長介面提示音，以免打斷語言節奏。

## 7. 循環規則

可選模式：

- 不循環：清單播完即停止。
- 整份清單循環。
- 單一項目循環。
- 困難項目加強：標記不熟後，在稍後位置再次出現。

預設採「不循環」，避免使用者忘記關閉後長時間重複播放。整份循環須由使用者主動開啟。

單一內容預設最多連續播放兩次；若選擇單項循環則不受此限制。系統應保留停止播放計時器，例如 10、20、30 分鐘或清單播完停止。

## 8. 播放控制

主畫面使用大型控制：

- 播放／暫停。
- 上一個／下一個。
- 重播目前項目。
- 標記「不熟」。
- 結束播放。

次要設定：

- 0.85／1.0／1.1 倍速。
- 中文解釋開啟或關閉。
- 例句開啟或關閉。
- 每項重複次數。
- 句子間隔。
- 循環與停止計時器。

若裝置支援 Media Session，鎖定畫面、耳機或系統通知區應提供播放／暫停、上一個與下一個。瀏覽器不支援時，網站仍須可在前景正常播放。

## 9. 畫面與字幕

純聽播放器主畫面顯示：

- 目前片語或對話名稱。
- 簡短中文意思。
- 播放進度與清單位置。
- 大型播放控制。
- 不熟標記。

英文逐句字幕預設可開啟，但移動情境不主動鼓勵閱讀。螢幕關閉或播放器縮小後，學習流程不能依賴字幕才能繼續。

## 10. 播放中斷與續接

- 電話、其他媒體或系統中斷時自動暫停。
- 使用者手動返回後，不假設自動繼續播放。
- 關閉頁面前保存目前清單、位置與播放設定。
- 下次提供「從上次位置繼續」或「重新產生今日清單」。
- 內容版本失效或被撤下時跳過該項，不嘗試播放舊的未授權副本。

## 11. 學習事件與進度

應記錄：

- 播放清單與播放單位版本。
- 開始、暫停、完成、跳過及重播。
- 實際播放秒數。
- 播放速度與是否包含中文或例句。
- 是否手動標記不熟。
- 是否完成一個需要回想的播放單位。

### 不直接代表掌握

- 音訊開始播放。
- 音訊在背景播完。
- 同一項目被循環多次。
- 累積很長的被動播放時間。

上述只計為曝露紀錄。只有使用者執行可判定的辨識或回想操作，才更新相應掌握度。

### MVP 可判定互動

為維持低視覺依賴，MVP 只提供：

- 「不熟」：降低信心並安排較早複習。
- 「想起來了」：可記為自我回報，但權重低於正式題目。
- 播放結束後，在安全且方便時完成一個簡短選擇或句塊題。

純聽期間沒有回應不代表答錯。

## 12. 音訊產生與快取

MVP 優先順序：

1. 經審核並預先產生的音訊。
2. Linux 本地 TTS 產生並經基本檢查的音訊。
3. 瀏覽器 TTS 作為降級方案。

同一教材版本應盡量使用固定音訊，避免每次播放的聲音、斷句與語速不同。瀏覽器 TTS 的可用聲音因裝置而異，不將特定音色視為必然存在。

需要保存的音訊 metadata：

- 語言與口音。
- 聲音識別資訊。
- 產生方式與版本。
- 語速。
- 對應的文字內容版本。
- 審核狀態。

## 13. 手機網頁技術驗證

正式將背景播放列為驗收條件前，需要在實機驗證：

- iPhone Safari。
- Android Chrome。
- 螢幕關閉後能否持續播放。
- Media Session 鎖定畫面控制。
- 耳機播放／暫停與切換按鍵。
- 電話或其他音訊中斷後的狀態。
- 多段短音訊連續播放時是否被系統暫停。
- PWA 安裝前後的行為差異。

若瀏覽器限制導致鎖定畫面後無法可靠切換多個短檔案，應測試將播放清單預先組合成較長音訊或使用連續媒體來源；在實測前不承諾特定方案。

## 14. MVP 驗收條件

- 使用者能在首頁兩次操作內開始今日純聽清單。
- 播放、暫停、上一個、下一個、重播與不熟標記可單手操作。
- 播放設定能保存並於下次沿用。
- 來電或媒體中斷不會錯誤記錄為完成學習。
- 被動播放只增加曝露紀錄，不直接提高掌握度。
- 至少完成 iPhone Safari 與 Android Chrome 的實機測試報告。
- 背景播放不可靠時，產品介面清楚說明限制並可正常使用前景播放。

## 15. 第一輪需要驗證

- 中文意思應在英文前、英文後，還是依新舊內容切換？
- 回想停頓預設 2、3 或 5 秒較自然？
- 使用者實際會使用整份循環還是停止計時器？
- 「不熟」與「想起來了」兩個控制是否足夠？
- 短音訊切換在鎖定畫面下是否穩定？
- 通勤時最適合的單次預設清單長度是多少？
