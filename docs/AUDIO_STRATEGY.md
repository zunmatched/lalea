# LaLea MVP 正式音訊策略

> 狀態：開發基線  
> 最後更新：2026-08-21  
> 決策：固定教材優先使用預生成音訊，本地 TTS 負責產生，瀏覽器 TTS 作為備援

## 1. 優先順序

1. 經審核的預生成音訊。
2. Linux 本地 TTS 產生、尚待完整人工審聽的音訊。
3. 瀏覽器 TTS 即時朗讀。

核心課程與正式聽力題不能只依賴瀏覽器 TTS，因為不同裝置的聲音、斷句、語速與可用音色不一致。

## 2. MVP 音訊內容

- 核心單字與片語。
- 每個核心詞義的一至兩個例句。
- 三堂初始課程的聽力稿。
- 固定分支對話。
- 純聽模式的英文片段。

中文解釋可在第一版使用瀏覽器或本地 TTS，但正式教材仍需確認斷句與自然度。

## 3. 產生流程

```text
已審核文字
→ 建立音訊產生任務
→ Linux 本地 TTS 產生候選音訊
→ 自動檢查檔案與時長
→ 人工試聽
→ 標記 approved
→ 學習播放器使用固定版本
```

文字更新時產生新的音訊版本，不讓舊音訊繼續對應已變更文字。

## 4. 音訊版本資料

- 語言與口音。
- 聲音／模型識別資訊。
- TTS 引擎與版本。
- 語速。
- 對應文字內容與版本。
- 檔案格式、大小、時長與 checksum。
- 產生、審核與發布時間。
- 審核狀態。

## 5. 聲音與速度

- 第一條英文路徑預設美式英語，待實際試聽確認。
- 正常版以自然職場語速為主，不為學習者過度逐字發音。
- 慢速優先由播放器調速至 0.85×；若品質不自然，再產生獨立慢速音訊。
- 對話角色使用可辨識但不誇張的不同聲音。
- 同一角色在同一課程中保持一致。

## 6. 格式與儲存

- MVP 優先選擇主要手機瀏覽器均可播放的格式。
- 正式格式需在 iPhone Safari 與 Android Chrome 實測後確定。
- 音訊檔不存入 PostgreSQL；資料庫只保存 metadata 與位置。
- 初期可使用 Linux 主機受控資料目錄。
- 音訊目錄需納入備份策略，但不提交 Git。
- URL 不直接暴露任意主機檔案路徑。

## 7. 播放與載入

- 下一個短片段可預載，但不一次下載完整大型清單。
- 使用者開始播放後才載入非必要音訊。
- 網路中斷時顯示可理解的狀態，不把載入失敗記為答錯。
- 切換題目、離開單元或播放另一段時，停止上一段音訊。
- 同一時間只允許一個主要播放器發聲。

## 8. 瀏覽器 TTS 降級

當固定音訊不存在或載入失敗時：

- 明確標記目前使用裝置語音。
- 保存語言、語速及可取得的 voice metadata。
- 不假設所有裝置都有同一音色。
- 聽力評量若高度依賴特定連音或語氣，不使用瀏覽器 TTS 代替正式音訊。

## 9. 純聽模式

- 以固定音訊片段建立清單。
- 需要驗證多個短檔連續播放與螢幕鎖定行為。
- 若鎖定畫面切換短檔不可靠，再測試預組合較長音訊。
- 被動播放只記曝露。
- 音訊中斷、跳過或未完整播放不記為完成。

## 10. 無障礙與控制

- 播放、暫停、重播、上一個、下一個有可讀標籤。
- 不進入題目便自動出聲。
- 字幕及逐字稿可取得。
- 調速不影響答案判定。
- 使用字幕、慢速或重播不扣分，但保存為學習輔助訊號。

## 11. 驗收條件

- 三堂初始課程的正式音訊已人工試聽。
- 音訊文字與教材版本一致。
- iPhone Safari 與 Android Chrome 可播放、暫停及重播。
- 播放失敗不會造成錯誤學習紀錄。
- 連續短片段與鎖定畫面已有實測結果。
- 固定音訊不存在時能安全降級。
- 網站服務無法藉音訊功能讀取主機任意檔案。
